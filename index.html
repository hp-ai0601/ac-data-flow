Do not mix these

Three secrets. "The token" is not one thing.

A. Shop token Shopify Admin API. Sync uses this. Cloud SQL shopify_store_connections.access_token_ref. Not in the browser cookie.
B. Merchant session Who is clicking the dashboard. Cookie ac_pivot_auth on app. HMAC. Identifies person + shop. No Admin token inside.
C. Ads / warehouse Google, Meta, Zendbox, Skio. integration_config.config_json access_token + refresh_token.

GCP Identity is how we log into the GCP console. Merchants never use it. Hosted Supabase email login is not the product login.

Secret A

Shopify shop token (sync)

Issued on GET /api/shopify-auth/offline/callback. Refresh: POST https://{shop}/admin/oauth/access_token grant_type=refresh_token.

After the store exists

Table shopify_store_connections
  • store_id
  • access_token_ref (shpat_, plain TEXT)
  • refresh_token (shprt_, plain TEXT)
  • access_token_expires_at (~60 min)
  • refresh_token_expires_at (~90 days, rotates)
  • status connected / disconnected / token_invalid

First-time onboarding, no store row yet

Table onboarding_progress
  • pending_offline_access_token
  • pending_refresh_token
  • keyed by shopify_user_id + shopify_store_domain

Copied onto shopify_store_connections at go-live. Not in the cookie.

Code: shopifyStoreReconnect.js, shopifyTokenService.js. Migration 20260712000001: tokens remain plaintext. At-rest app encryption is not done.

How ac_pivot_auth is generated

HMAC. Not Shopify. Not GCP Identity. Not GoTrue.

1
API builds JSON: type, shopify_user_id, shopify_email, shopify_store_domain, account_owner, app_user_id, store_id, exp. File: backend/services/pivotAuthHandoff.js buildPivotHandoffIdentity.
2
body = base64url(JSON). sig = HMAC-SHA256(SHOPIFY_SESSION_SECRET, body) as base64url. Token = body.sig. Same function for 15-min URL handoff, 7-day cookie, 2-min Bearer. Only TTL changes.
3
API 302s to https://app.agentic-cart.com/auth/complete?pivot_token=... FRONTEND_URL. Browser is now on Cloud Run web.
4
GET /api/pivot-handoff on web verifies HMAC with the same secret, Set-Cookie ac_pivot_auth, drops the query param. If secrets differ between web and api, this redirect lands on login with "Session handoff failed".

Q1 + Q2

What Cloud Run api does with the callback

5
Shopify returns shop + hmac. /install forwards to /api/shopify-auth/connect. Nonce written to Cloud SQL oauth_state. Then 302 to {shop}/admin/oauth/authorize (per-user grant). Redirect URI: SHOPIFY_IDENTITY_REDIRECT_URI on api.agentic-cart.com.
6
Consent. GET /api/shopify-auth/callback?code=&shop=&state=. oauth_state row deleted (no replay). POST https://{shop}/admin/oauth/access_token with client_id, client_secret, code.
7
Response: access_token + associated_user (staff id, email, account_owner). Written onto ac.shopify.sid (15 min). app_users found/created by email. store_members.shopify_user_id patched if they already belong to this shop.
8
Then offline handshake /api/shopify-auth/offline/callback. Expiring shop token saved as Secret A (shopify_store_connections or onboarding_progress).
9
Browser sent back to https://app.agentic-cart.com/auth/complete?pivot_token=... /api/pivot-handoff sets ac_pivot_auth (7 days). Then dashboard or store picker (GET /api/shopify-auth/my-stores).
Q2 Auth process

Every later dashboard request

1
Browser only talks to https://app.agentic-cart.com. Sends ac_pivot_auth. Never gets a Cloud SQL password. Never calls PostgREST.
2
BFF /api/pivot/* reads cookie, adds Authorization Bearer, copies x-active-store-id (frontend/lib/apiClient.ts), calls api.agentic-cart.com.
3
requireUserOrPivot: product path is the Shopify pivot Bearer. Login button is Shopify OAuth, not email. Leftover hosted-Supabase JWT login is gone on main (#253). POST /api/me/tenant is 410.
4
requireTenantOrPivot: active store_members for that app_users.id. Preferred store is x-active-store-id or shop domain on the token. Not a member of the requested store: 403. No fallback to another shop.
5
requirePivotStoreScope: no req.storeId = refuse. Dashboard queries .eq store_id. That is why test1 cannot see NMU.

Q4 Isolation

How RLS is implemented

Still in the schema (not the live gate)

ENABLE ROW LEVEL SECURITY from hosted Supabase. Policy:

tenant_id IN (SELECT tenant_id FROM user_tenants WHERE user_id = auth.uid())

auth.uid() is GoTrue. Live api uses PostgREST service_role, which bypasses RLS. user_tenants is not how merchants sign in.

Live gate (Express)
  1. Cookie / Bearer decodes to a Shopify person.
  2. store_members.status = active on the requested store.
  3. req.storeId set. Queries .eq("store_id", req.storeId). Sibling shop without membership: 403.

requireUserOrPivot + requireTenantOrPivot + requirePivotStoreScope
